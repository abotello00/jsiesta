Pseudopotentials and basis sets
===============================

Pseudopotentials
----------------

jsiesta reads norm-conserving pseudopotentials in **PSML** format only (``.psf`` and ``.vps`` files are not
supported). For each species label ``X`` of ``ChemicalSpeciesLabel`` the file ``X.psml`` is searched in
``--pseudo-dir``, in the directory of the input file, and in the directories of ``SIESTA_PS_PATH``.

The `PseudoDojo <http://www.pseudo-dojo.org>`_ tables are distributed in PSML format (choose *psml* as format);
the scalar-relativistic sets serve all calculations without spin-orbit coupling, the fully relativistic sets
are needed for ``Spin spin-orbit``. ``examples/pseudos`` holds the PseudoDojo PBE files for H, C, O and Si used
by the tutorials.

The functional of the calculation should be the one the pseudopotential was generated with.

Basis sets generated by jsiesta
-------------------------------

By default the basis is generated from the pseudopotential, following SIESTA's recipe:

* the first radial function of each valence shell is the pseudo-atomic orbital confined to a radius set by
  ``PAO.EnergyShift`` (a smaller shift gives longer, more accurate and more expensive orbitals);
* further zetas are split-valence functions with radii set by ``PAO.SplitNorm``;
* polarisation orbitals (the ``P`` in ``DZP``) are obtained by perturbing the highest valence shell with an
  electric field.

.. list-table::
   :header-rows: 1
   :widths: 14 40 46

   * - Size
     - Radial functions per valence shell
     - Typical use
   * - ``SZ``
     - 1
     - Quick tests, very large systems
   * - ``DZ``
     - 2
     -
   * - ``DZP``
     - 2 + 1 polarisation shell
     - The standard choice
   * - ``TZP``, ``TZ2P``
     - 3 + 1 or 2 polarisation
     - Convergence checks

.. admonition:: Hydrogen

   The default split norm gives hydrogen a second zeta that is too extended. Set ``PAO.SplitNormH 0.5``
   (``split_norm_h=0.5`` in Python), as SIESTA recommends: with a DZP basis and PBE it changes the bond length of
   H\ :sub:`2` from 0.777 to 0.748 Ang (converged PBE: 0.750) and lowers the energy by 0.24 eV.

The output of every run lists the radial functions and their radii; ``jsiesta in.fdf --check`` prints them
without running the calculation.

.. admonition:: How close is a generated basis to SIESTA's?

   The generator is an independent implementation of SIESTA's procedure, not a copy of it. Radii and trends
   agree with SIESTA, and with an identical explicit ``PAO.Basis`` the Si total energies of the two codes differ
   by a constant 28 meV per cell (decision D-040). It is not expected to reproduce SIESTA total energies to the
   meV. When you need the *same* basis as a SIESTA run, use ``User.Basis`` (below). For elements with semicore
   or d valence states, check the list of generated shells and use ``PAO.Basis`` if the automatic choice of the
   polarisation shell is not the one you want.

Explicit shells: ``PAO.Basis``
------------------------------

.. code-block:: text

   %block PAO.Basis
   Si  2                    # label, number of shells [, ionic charge]
     n=3  0  2  P 1  E 40.0 4.5      # n, l, zetas; P: polarisation; E: soft confinement V0 (Ry), ri (Bohr)
       6.0  4.2                      # cut-off radius of each zeta (Bohr); 0.0 0.0 = automatic
     n=3  1  2
       7.0  5.0
   %endblock PAO.Basis

Supported: ``n=``, ``l``, number of zetas, ``P [n]``, ``E V0 ri``, ``S split_norm``, an ionic charge, and radii
that are all given or all zero. Not supported (an error is raised): shells without ``n=``, charge confinement
(``Q``), filtering (``F``), scale factors other than 1. Species absent from the block use ``PAO.BasisSize``.

Using the basis of a SIESTA run
-------------------------------

With ``User.Basis T`` the orbitals are read from ``<Label>.ion.xml``, which SIESTA writes in every run. The two
codes then work with identical basis functions; this is the configuration in which jsiesta is validated against
SIESTA (see :doc:`../development/index`).

In Python: ``jax_siesta.app.build_species(label, psml, ion_path="Si.ion.xml")``.

Optimising a basis
------------------

:func:`~jax_siesta.species.basis_opt.optimize_basis_enthalpy` minimises the basis enthalpy (energy plus a
pressure times the volume of the orbitals) over the cut-off radii and confinement parameters, and
:func:`~jax_siesta.species.basis_opt.format_pao_basis_block` writes the result as a ``PAO.Basis`` block that
both codes read. See :doc:`../api/species`.
