Contributing
============

Set-up
------

.. code-block:: bash

   make venv                           # environment and editable install
   LIBXC_ROOT=/path/to/libxc make ffi  # compiled kernels

Checks
------

.. list-table::
   :header-rows: 1
   :widths: 24 76

   * - Command
     - What it runs
   * - ``make lint``
     - ruff
   * - ``make typecheck``
     - mypy on ``jax_siesta`` and ``kg``
   * - ``make docs``
     - Doxygen, then Sphinx with warnings as errors (this site)
   * - ``make tutorials``
     - Executes the tutorial scripts and stores the notebooks with their outputs
   * - ``make kg``
     - Rebuilds the knowledge graph and the architecture diagrams
   * - ``make test``
     - pytest with JUnit output in ``reports/``
   * - ``make test-refs``
     - The same, but a missing external reference fails instead of skipping
   * - ``make check``
     - All of the above except the tutorials

The continuous integration runs ruff, mypy and the documentation build, and publishes this site from ``main``.
The physics tests need the compiled library, Libxc and the SIESTA references, so they run locally.

SCF tests compile large functions and can use several GB. On a workstation run them under a memory limit, for
example ``systemd-run --user --scope -p MemoryMax=6G .venv/bin/python -m pytest tests/test_app_interface.py``.

Conventions
-----------

**State is explicit.** Functions take what they need as arguments and return new objects; there are no module
globals holding simulation state.

**Stages sit behind protocols.** Extend by implementing a protocol of ``jax_siesta.core.protocols``.

**Compile once per shape.** Compiled functions live at module level and receive geometry-dependent arrays as
arguments. Do not close over arrays inside ``jax.jit``: they become constants of the executable.

**Docstrings are part of the code.** Every public function, class and module has the sections ``Theory``,
``Algorithm``, ``Invariants`` and ``SIESTA Mapping`` (plus ``Parameters`` and ``Returns`` where they apply), with
units stated. A test fails when a public entity lacks them. In these sections avoid a colon at the end of the
first sentence of a paragraph: the documentation builder reads ``text: more text`` as a definition.

**Every physics term gets an external check and an identity check.** If the reference is not available on your
machine, write the test anyway with ``@pytest.mark.external_refs(...)`` and say that it has not run.

**Tests are small.** Seconds per test and under 1 GB: the smallest system that exercises the path, a low mesh
cutoff, one case per code path.

**Claims carry numbers.** A statement about accuracy or speed in a docstring or log names the system, the
machine and what was not measured.

Recording a change
------------------

A change that alters behaviour adds an entry ``D-NNN`` to ``logs/DECISIONS.md`` (why, decision, measured effect,
what was not checked), appends to ``logs/WORK_LOG.md`` and updates ``MEMORY.md`` (the status page of this site).

Adding to this documentation
----------------------------

* Hand-written pages are ``.rst`` files under ``docs/``; the API pages include fragments generated by
  ``docs/conf.py`` from the packages listed in ``API_SECTIONS``. A new package must be added to a section there
  (the build fails otherwise) and described in the introduction of that section.
* Tutorials are Python scripts in ``docs/tutorials`` in the "percent" format (``# %%`` cells). ``make
  tutorials`` converts them to notebooks and executes them; commit both the script and the notebook.
